QUESTION 3: What's the best way to request an NVIDIA A10 GPU node when configuring a pod on Nautilus?

RESPONSE:
# What's the best way to request an NVIDIA A10 GPU node when configuring a pod on Nautilus?

Based on NRP documentation, here's how to request an NVIDIA A10 GPU node for your pod:

## GPU Resource Request Configuration

To request an A10 GPU, you need to specify both the GPU resource and use node selection to target A10-equipped nodes:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: my-a10-pod
spec:
  containers:
  - name: gpu-container
    image: your-image
    resources:
      requests:
        nvidia.com/gpu: 1  # Request 1 GPU
      limits:
        nvidia.com/gpu: 1
  nodeSelector:
    nvidia.com/gpu.product: NVIDIA-A10  # Target A10 nodes specifically
```

## Alternative Node Affinity Approach

For more flexible scheduling, use nodeAffinity:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: my-a10-pod
spec:
  containers:
  - name: gpu-container
    image: your-image
    resources:
      requests:
        nvidia.com/gpu: 1
  affinity:
    nodeAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        nodeSelectorTerms:
        - matchExpressions:
          - key: nvidia.com/gpu.product
            operator: In
            values:
            - NVIDIA-A10
```

QUESTION 4: How do users specify multiple GPU types (e.g., A100 and A10) in a multi-GPU job on NRP?

RESPONSE:
# How do users specify multiple GPU types (e.g., A100 and A10) in a multi-GPU job on NRP?

## Kubernetes GPU Scheduling Limitations

**Important:** Kubernetes does not support requesting multiple different GPU types within a single pod or container. Each pod can only request one type of GPU resource.

## Recommended Approaches

### 1. Use Multiple Pods/Containers
Create separate pods for different GPU types and coordinate them:

```yaml
# Pod 1: A100 GPU workload
apiVersion: v1
kind: Pod
metadata:
  name: a100-worker
spec:
  containers:
  - name: a100-container
    image: your-image
    resources:
      requests:
        nvidia.com/gpu: 1
  nodeSelector:
    nvidia.com/gpu.product: NVIDIA-A100-SXM4-40GB
---
# Pod 2: A10 GPU workload
apiVersion: v1
kind: Pod
metadata:
  name: a10-worker
spec:
  containers:
  - name: a10-container
    image: your-image
    resources:
      requests:
        nvidia.com/gpu: 1
  nodeSelector:
    nvidia.com/gpu.product: NVIDIA-A10
```

### 2. Flexible Scheduling (Either/Or)
If your workload can run on either GPU type, use nodeAffinity with OR conditions:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: flexible-gpu-pod
spec:
  containers:
  - name: gpu-container
    image: your-image
    resources:
      requests:
        nvidia.com/gpu: 1
  affinity:
    nodeAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        nodeSelectorTerms:
        - matchExpressions:
          - key: nvidia.com/gpu.product
            operator: In
            values:
            - NVIDIA-A100-SXM4-40GB
            - NVIDIA-A10
```

### 3. Kubernetes Job with Multiple Workers
Use a Job controller to manage multiple GPU-specific workers:

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: multi-gpu-job
spec:
  parallelism: 2
  completions: 2
  template:
    spec:
      containers:
      - name: worker
        image: your-image
        resources:
          requests:
            nvidia.com/gpu: 1
      # Use different node selectors via multiple Job definitions
```

RESPONSE:
# How do users launch a GUI-enabled desktop container (GLX or EGL) via Coder on NRP?

## GPU-Enabled Desktop Setup via Coder

To launch a GUI-enabled desktop container through Coder on NRP, you'll need to use a Coder workspace template configured for GPU desktop environments.

## Performance Considerations: GPU vs CPU Encoding

### GPU Hardware Encoding (Recommended)
**Advantages:**
- **Lower CPU usage** - Offloads encoding from CPU to dedicated GPU encoding units
- **Better performance** - Hardware acceleration provides smoother experience
- **Higher resolution support** - Can handle 4K+ resolutions efficiently
- **Lower latency** - Hardware encoding reduces delay in remote sessions

**Requirements:**
- GPU with encoding support (NVENC for NVIDIA GPUs)
- Proper GPU drivers and encoding libraries
- Container configured with GPU access

### CPU Software Encoding (Fallback)
**When to use:**
- No GPU available or GPU lacks encoding support
- Debugging encoding issues
- Very simple workloads with minimal graphics

**Trade-offs:**
- **Higher CPU usage** - Can consume 50-80% of CPU resources
- **Limited resolution** - May struggle with high resolutions
- **Higher bandwidth** - Less efficient compression requires more network
- **Potential stuttering** - CPU encoding may cause frame drops

## Container Options

### GLX Desktop Container
```yaml
# For X11/legacy OpenGL applications
image: docker-nvidia-glx-desktop
```
**Use when:**
- Running traditional X11 GUI applications
- Need legacy OpenGL compatibility
- Direct X11 forwarding required

### EGL Desktop Container
```yaml
# For headless/offscreen rendering
image: docker-nvidia-egl-desktop
```
**Use when:**
- Headless rendering workflows
- Modern OpenGL contexts
- Server environments (more stable)
- Offscreen rendering needs

## Coder Workspace Configuration

When setting up your Coder workspace:

1. **Select GPU-enabled template** - Choose a template with GPU desktop support
2. **Configure GPU access** - Ensure workspace has GPU resource requests
3. **Set display variables** - Configure DISPLAY and GL environment variables
4. **Access via web UI** - Use Coder's web interface to connect to desktop

## Best Practices

- **Prefer EGL for server environments** - More stable for remote access
- **Use GLX for legacy applications** - When specific X11 compatibility needed
- **Enable GPU encoding when available** - Significantly better performance
- **Monitor resource usage** - Check CPU/GPU utilization during use

**Sources:** https://nrp.ai/documentation/userdocs/running/gui-desktop/#performance-considerations

# Which container—docker-nvidia-glx-desktop or docker-nvidia-egl-desktop—should users prefer, and why?

## Container Comparison and Recommendations

### EGL Desktop Container (Recommended for Most Users)
**Container:** `docker-nvidia-egl-desktop`

**Why Choose EGL:**
- **Better server stability** - EGL is designed for headless/server environments
- **More efficient** - Less overhead than full X11 stack
- **Modern OpenGL support** - Better support for contemporary graphics APIs
- **Remote access optimized** - Better suited for web-based remote desktop access
- **Fewer compatibility issues** - Less likely to have display server conflicts

**Best for:**
- Remote desktop sessions via Coder
- Modern applications and development environments
- Jupyter notebooks with visualization
- Machine learning workloads with plotting
- General-purpose GPU-accelerated computing

### GLX Desktop Container (Legacy/Specific Use Cases)
**Container:** `docker-nvidia-glx-desktop`

**Why Choose GLX:**
- **X11 compatibility** - Required for some legacy applications
- **Direct X11 forwarding** - When you need native X11 protocol support
- **Legacy OpenGL apps** - Applications that specifically require GLX context
- **Traditional Linux desktop** - Full X11 desktop environment experience

**Best for:**
- Legacy scientific applications requiring X11
- Applications that specifically need GLX context
- Traditional X11 forwarding workflows
- Debugging X11-specific issues

## Performance Considerations

Both containers support the same GPU encoding capabilities:

### GPU Hardware Encoding (Both Support)
- **Lower CPU usage** - Hardware acceleration reduces CPU load
- **Better performance** - Smoother remote desktop experience
- **Higher resolution support** - Can handle 4K+ efficiently
- **Lower latency** - Hardware encoding reduces delay

### When GPU Encoding Unavailable
- **Higher CPU usage** - Software encoding uses 50-80% CPU
- **Limited resolution** - May struggle with high resolutions
- **Higher bandwidth** - Less efficient compression
- **Potential stuttering** - CPU encoding may cause frame drops

## Recommendation Summary

**Choose EGL** (`docker-nvidia-egl-desktop`) for:
✅ Most users and use cases
✅ Remote access via Coder web interface
✅ Modern development environments
✅ Better stability and performance

**Choose GLX** (`docker-nvidia-glx-desktop`) only when:
⚠️ Legacy applications specifically require X11/GLX
⚠️ Direct X11 protocol forwarding needed
⚠️ Troubleshooting X11-specific compatibility issues
